RailMind deployment — Railway (Postgres) + Streamlit Cloud (app)\n\nOverview\n--------\nThis guide walks through a recommended deployment: Railway for managed Postgres, Streamlit Cloud for the public-facing web app.\n\nPart 1 — Railway Postgres (click-by-click)\n1. Sign in to Railway at https://railway.app. Use GitHub SSO for easiest integration.\n2. Create a new project (New Project -> Provision Postgres).\n3. Railway will provision a Postgres plugin and show DATABASE_URL — copy it.\n4. (Optional) In Railway, open the project console and run the seed command:\n     - python db/init_postgres.py — but you must set DATABASE_URL as an environment variable in the Railway project first.\n   Alternatively, run the seeding locally using the DATABASE_URL Railway gave you.\n\nPart 2 — Streamlit Cloud deployment\n1. Go to https://share.streamlit.io and create a new app.\n2. Link your GitHub repo: in-ydv/train_traffic_control and pick the main branch.\n3. Set the app to use the default start command (streamlit run app.py). Set an environment variable:\n   - DATABASE_URL = the Railway database URL copied earlier.\n4. Deploy the app. Streamlit Cloud will install dependencies from requirements.txt and start the app.\n\nPart 3 — Test after deployment\1. On your machine (or on Railway console), run:\n   - python db/check_connection.py (after exporting DATABASE_URL)\n2. Open the Streamlit Cloud URL and run a demo scenario (Reset / Load scenario).\n3. Confirm the DB contains seeded data; in Railway console you can inspect the stations and 	rains tables.\n\nTroubleshooting\n- If the app falls back to SQLite, it means DATABASE_URL was not set in the Streamlit Cloud environment.\n- Use un_init_pg.ps1 locally to start docker-based Postgres if you want to avoid cloud provider credentials.\n\nSecurity note\n- Do not commit production DB credentials into the repo.
